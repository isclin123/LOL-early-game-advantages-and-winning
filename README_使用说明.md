## 当前研究主线

核心目标是研究前期优势与获胜概率的关系，以及模型在其他年份、赛区是否仍然适用。

1. 15 分钟的经济、击杀、经验和补刀差与最终胜负有什么关系？
2. 经济优势与胜负的关系是否随版本变化？
3. 韩国赛区训练的模型在下一年及其他赛区的预测表现如何？

对应的模型是一组共享结果变量和前期指标的逻辑回归、贝叶斯分层逻辑回归、随机森林。K-means 保留为辅助描述，不另开多项核心研究问题。主分析统一预测 15 分钟时的最终蓝方获胜概率；10 分钟比较只作为以后可选的敏感性分析。

## 分层模型的含义

第一层是比赛及其四项前期指标；第二层是游戏版本，允许版本截距和经济差系数变化。这里没有虚构的版本数值解释变量，也不把只有一个开发赛区的 league 当成可估计的赛区效应。2025 年测试版本全部没有出现在 2024 年开发数据中，因此预测时需要对新版本效应进行平均，不能先用测试胜负估计这些效应。

## 怎么运行分析文件

`analysis/LoL_Project.Rmd` 现在两种方式都能跑：在 RStudio 里点 Knit，或者在 RStudio 里逐块运行（Run All Chunks）。文件开头会自己定位项目目录——knit 时用 knitr 给出的输入路径，逐块运行时问 RStudio 当前打开的文档，都拿不到时从工作目录向上找 `audit/` 和 `data/`；三条都失败会直接报错并说明该怎么办，而不是抛出看不懂的 `invalid '''path''' argument`。

有两点和本机环境有关。第一，`C:/Users/isclin/Documents/.Rprofile` 里有一句 `setwd("C:/Users/isclin/Documents/R_file")`，每个非 `--vanilla` 的 R 会话启动后工作目录都会被改到那里；Rmd 已经不受它影响，但自己写零散脚本时要留意，必要时删掉这句或改用项目内的 `.Rprofile`。第二，在命令行渲染要先让 rmarkdown 找到 pandoc，例如把环境变量 `RSTUDIO_PANDOC` 指向 RStudio 自带的 `resources/app/bin/quarto/bin/tools`；在 RStudio 里点 Knit 不需要这一步。

第 7 节及以后的代码块依赖第 1—6 节建立的 `train`、`validation` 等对象，所以单独运行后面的块会报对象找不到；先 Run All Chunks 或从头顺序运行。
