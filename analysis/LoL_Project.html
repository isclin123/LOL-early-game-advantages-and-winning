1. Purpose and current scope

This is the main analysis file for the project. All preprocessing and statistical analyses are written here, section by section. The current version completes preprocessing, exploratory data analysis (EDA) of the initial training set, and the logistic regression baseline with its diagnostics and validation scores. It does not score either 2025 test set; those partitions are read for structural checks only and stay unscored until the specification is frozen in section 9.

The outcome is whether the blue-side team wins a game. The prediction time is 15 minutes. The four predictors are blue-minus-red differences in gold, kills, experience points, and creep score. Creep score counts minions and monsters killed. A game is one observation; the two teams in a game are not independent observations.

The three research questions concern the relationship between early advantages and winning, differences across game patches, and prediction in a later year and another league. Patch means the recorded game version. These are observational data, so an association does not establish a causal effect.

The course folder does not currently contain lecture notes for this capstone. The instructor’s proposal feedback and the revised analysis plan guide this file. The historical ten-question list is not the current analysis specification.

2. Sources and decisions made before analysis

The raw files are the saved September 2026 snapshot from ChainCC. The provider’s methodology lists several upstream sources. We use the local snapshot rather than silently downloading a newer version. File-year labels do not always equal the actual year of every game; we select games using the recorded match date.

A previous source check compared 11 selected training games with Games of Legends, covering eight patches, extreme gold differences, and one zero creep-score difference. All 44 early-feature comparisons agreed. Dates, sides, results, patch numbers, and durations also agreed. See the source-check report for game links and evidence. This purposeful sample does not verify every record, and the websites may share upstream errors.

We retain the following decisions from the approved design:

  • Keep one blue-side record per paired game and define every difference as blue minus red.
  • Exclude games with invalid early measurements. The Chinese league in the original candidate pool has nonpositive early gold and is not used.
  • Keep valid extreme values and genuine zero differences. Do not trim or winsorize them merely because they are unusual.
  • Stop for unexpected missing values, duplicate keys, or new inconsistencies rather than silently filling values or choosing one duplicate.
  • Preserve raw team names and team IDs. Record known historical display-name differences separately; do not automatically merge team identities across years.
  • Keep the fixed chronological and geographic splits. Learn centering and scaling only from the current training set.

These decisions are not chosen by comparing model performance. Any later change that alters the cohort, outcome, or split must be recorded here before final testing.

4. Training, validation and test design

We use a chronological split within the Korean league. Games from January through June 2024 form the initial training set. Games from July through September 2024 form the validation set. This asks whether choices made with earlier games remain useful for later games from the same league. It also reduces leakage that would arise from randomly mixing earlier and later games.

There are two separate 2025 test sets. Korean games measure transfer to a later year within the source league. European regional games measure transfer to another league and a later year. European games from 2024 remain outside model development. All matches from the same series occur within one partition under these date rules; we verify that property below.

After model settings are chosen using only training and validation data, we will refit the selected recipe on all 482 Korean games from 2024. This is the union of training and validation, not an extra independent dataset. Both 2025 tests remain outside preprocessing choices, tuning, prior selection, cluster-count selection, and calibration adjustments.

4.1 Fit preprocessing parameters using training data only

We keep the original units and add standardized copies for later methods that need them. A standardized value subtracts the training mean and divides by the training standard deviation. This is particularly useful for clustering and for expressing Bayesian priors on comparable scales. It is not essential for a random forest.

There is no imputation, outlier removal, feature selection, or outcome-based transformation in this step. Future final refitting will recompute the same recipe on the 482-game source set, only after choices have been frozen.

scaling <- data.frame(variable = features,
                      center = vapply(train[features], mean, numeric(1)),
                      scale = vapply(train[features], sd, numeric(1)), row.names = NULL)
stopifnot(all(is.finite(scaling$scale)), all(scaling$scale > 0))
apply_scaling <- function(d, recipe) {
  for (i in seq_len(nrow(recipe))) {
    v <- recipe$variable[i]
    d[[paste0(v, "_z")]] <- (d[[v]] - recipe$center[i]) / recipe$scale[i]
  }
  d
}

7. Logistic regression baseline

7.1 Scoring code shared by every later model

These functions are defined once and reused by the later sections, so every model is judged by identical code. Log loss is the primary measure, with Brier score and calibration as support. The area under the receiver operating characteristic curve (AUC) is supplementary: it measures ranking only and ignores whether the probabilities are numerically correct. The helpers are checked against cases whose answers can be worked out by hand.

log_loss <- function(y, p, eps = 1e-15) {
  p <- pmin(pmax(p, eps), 1 - eps)
  -mean(y * log(p) + (1 - y) * log(1 - p))
}
brier_score <- function(y, p) mean((p - y)^2)
auc_roc <- function(y, p) {
  n1 <- sum(y == 1); n0 <- sum(y == 0)
  (sum(rank(p)[y == 1]) - n1 * (n1 + 1) / 2) / (n1 * n0)
}
score_predictions <- function(label, set, y, p) {
  data.frame(model = label, set = set, games = length(y),
             log_loss = log_loss(y, p), brier = brier_score(y, p),
             auc = auc_roc(y, p), mean_predicted = mean(p), observed = mean(y))
}
calibration_table <- function(y, p, breaks = seq(0, 1, 0.2)) {
  bin <- cut(p, breaks = breaks, include.lowest = TRUE)
  do.call(rbind, lapply(levels(bin), function(b) {
    k <- which(bin == b)
    data.frame(bin = b, games = length(k),
               mean_predicted = if (length(k)) mean(p[k]) else NA_real_,
               observed = if (length(k)) mean(y[k]) else NA_real_)
  }))
}
